# Market Combat API

Договор между приложением и сервером. Сейчас его выполняет заглушка внутри приложения (`src/mock-server`). Потом его же выполнит сервер на Go по адресу `https://api.ahilespelid.ru`. Типы описаны в `src/api/contract.ts`, этот файл — их человеческая версия.

## Общие правила

- Формат — JSON по HTTPS. Авторизация: заголовок `Authorization: Bearer <token>`.
- Суммы указываются в целых ABIE (валюты игр — в целых единицах своей валюты), время — в миллисекундах Unix.
- Ошибка возвращается так: `{ "error": { "code": "...", "message": "..." } }`.

| Код ошибки | HTTP | Когда |
|---|---|---|
| `unauthorized` | 401 | нет сессии или она истекла |
| `invalid_input` | 400 | неверные данные в запросе |
| `invalid_code` | 400 | неверный код из письма |
| `challenge_expired` | 410 | попытка входа истекла или уже использована |
| `insufficient_funds` | 409 | не хватает ABIE |
| `rate_limited` | 429 | слишком часто |
| `not_found` | 404 | нет такого объекта |
| `forbidden` | 403 | действие запрещено (например, игра чужой вселенной) |
| `conflict` | 409 | состояние не позволяет (например, персонаж не выбран) |
| `network` | — | только в приложении: запрос не дошёл до сервера |

## Вход

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /v1/auth/email/start` | `{ email }` | `{ challengeId, expiresAt }`. На почту уходит код из 6 цифр, он действует 10 минут. Повторная отправка возможна не раньше чем через 30 с. |
| `POST /v1/auth/email/verify` | `{ challengeId, code }` | `AuthResult`. После 5 неверных кодов попытка сгорает. |
| `POST /v1/auth/telegram/start` | `{}` | `{ challengeId, expiresAt, botUrl }`. Ссылка открывает бота с одноразовым параметром `start=login_…`. |
| `POST /v1/auth/phone/start` | `{}` | То же, но `start=phone_…`: бот просит поделиться номером телефона (бесплатно, без SMS). |
| `GET /v1/auth/challenges/{id}` | — | `{ status: "pending" }`, `{ status: "expired" }` или `{ status: "confirmed", ...AuthResult }`. Подтверждённый вход отдаётся один раз. |
| `POST /v1/auth/google` | `{ idToken }` | `AuthResult`. Сервер проверяет Google ID token. |
| `POST /v1/auth/logout` | `{}` | `{ ok: true }` |

`AuthResult = { session: { token, expiresAt }, account, profile, isNew }`. Сессия действует 30 дней. Первый вход с новым способом создаёт аккаунт, профиль и кошелёк, на который зачисляется 100 ABIE.

Как бот подтверждает вход на настоящем сервере: Telegram присылает на webhook сервера сообщение `/start login_<nonce>` или контакт игрока. Сервер находит попытку по `nonce` и привязывает Telegram id или номер телефона. В заглушке это делает `server.dev.telegramConfirm`.

## Профиль

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /v1/me` | — | `{ account, profile }` |
| `PATCH /v1/me/profile` | `{ nickname? }` | `Profile`. Ник — от 2 до 16 символов. |

`Profile = { accountId, nickname, character, gender, genderChangedAt, skins, stats, respect }`. Пока персонаж не выбран, `character` и `gender` равны `null`.

## Персонаж и внешность

Персонажи: `valdberik`, `ozonik`, `avitos`, `yandos`. Пол: `m`, `f`. В `skins` лежит коллекция скинов игрока: 4 бесплатных персонажа есть у всех с самого начала, новые скины будут добавляться туда же.

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /v1/me/character` | `{ character, gender }` | `Profile`. Первый выбор, бесплатно. 409 `conflict`, если персонаж уже выбран. 403, если скина нет в коллекции. |
| `POST /v1/me/character/change` | `{ character, requestId }` | `{ profile, tx }`. Списывает 5 000 ABIE (операция `character_change`), статистика, рейтинги, история и ABIE сохраняются. 409 `insufficient_funds`, если не хватает. Повтор с тем же `requestId` возвращает тот же результат и не списывает второй раз. |
| `POST /v1/me/gender` | `{ gender }` | `Profile`. Бесплатно, не чаще раза в неделю (`genderChangedAt` — время последней смены). Раньше срока — 429 `rate_limited`. Первый выбор пола вместе с персонажем в лимит не входит. |

## Кошелёк ABIE

Отдельный сервис со своей базой (`abie_wallet`). Каждая операция имеет уникальный `id`: повтор с тем же `id` ничего не меняет, уйти в минус нельзя, история только дописывается.

| Запрос | Ответ |
|---|---|
| `GET /v1/wallet` | `{ currency: "ABIE", balance }` |
| `GET /v1/wallet/transactions?limit=20&cursor=` | `{ items: WalletTx[], nextCursor }`, новые сверху |

`WalletTx = { id, ts, kind, amount, balanceAfter, ref? }`. Виды операций `kind`:

| kind | Что это |
|---|---|
| `welcome` | приветственный бонус |
| `match_reward` | приз за место (старые матчи; призов больше нет) |
| `character_change` | смена персонажа |
| `currency_buy` | игрок купил валюту игры за ABIE |
| `currency_return` | валюта игры вернулась в ABIE после матча |
| `currency_sale`, `currency_payout` | те же две операции со стороны счёта платформы |

Счёт платформы (`platform`) — обычный счёт в том же кошельке. Туда приходят ABIE, потраченные на валюты игр, и оттуда выплачивается то, что возвращается из матчей. Только этот счёт может уйти в минус: это значит, что игроки выиграли у платформы больше, чем она получила.

## Игры и их валюты

Реестр игр хранится на сервере. Запись появляется, когда игру загружают на платформу, и после этого не меняется никогда. Запроса на изменение игры в API нет.

`GameEntry = { id, universes, currency, publishedAt }`:
- `universes` — список вселенных (персонажей), в которых видна игра, или `"all"` для общей игры;
- `currency` — своя валюта игры или `null`: `{ code, rate: { abie, units }, settle }`.

Правила валют:
- Валюта игры покупается только за ABIE.
- Курс — целые числа: `abie` ABIE покупают `units` единиц валюты. Покупка идёт целыми порциями по курсу. Курс задаётся один раз при загрузке игры и не меняется никогда.
- Потраченные ABIE уходят на счёт платформы.
- `settle: "match"` — после матча всё, что вернул матч, пересчитывается обратно в ABIE по тому же курсу. С прибыли платформа берёт 10% (округление вверх до целой единицы валюты), с убытка ничего. Сумма в ABIE округляется до целого по обычным правилам.
- `settle: "none"` — валюта остаётся в игре. Общего обратного обмена валюты игры на ABIE пока нет: решим позже.

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /v1/games` | — | `{ items: GameEntry[] }` |
| `GET /v1/games/{id}/currency` | — | `{ game, code, balance }` |
| `POST /v1/games/{id}/currency/buy` | `{ lots, requestId }` | `{ tx, currency }`. Списывает `lots × abie` ABIE, начисляет `lots × units`. Повтор с тем же `requestId` ничего не меняет. 409 `insufficient_funds`, если не хватает ABIE; 409 `conflict`, если персонаж не выбран; 403, если игра не из вселенной игрока. |

«Дуэль на графике»: общая игра (`"all"`), валюта — доллары дуэли `DUSD`, курс 1 ABIE = $100, `settle: "match"`.

На сервере Go в Percona неизменность записи держит сама база: схема и триггер — в `docs/db/games.sql`.

## Матчи

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /v1/matches` | `{ game, stakeLots, requestId }` | `{ matchId, game, seed, startedAt, stake, stakeLots, tx }`. Seed выбирает сервер. Для игры с валютой ставка — `stakeLots` целых порций курса. Недостающая валюта покупается за ABIE в той же операции (`tx`). Повтор с тем же `requestId` возвращает тот же матч и ничего не списывает. |
| `POST /v1/matches/{id}/finish` | `{ place, equity, actions }` | `{ matchId, place, stake, equity, profit, fee, payout, net, tx, profile }`. Повтор возвращает тот же ответ, ничего не выплачивается второй раз. |

- Без выбранного персонажа играть нельзя (409 `conflict`). Игра чужой вселенной — 403.
- Призов за места нет: игрок торгует на свои. `equity` — его баланс в валюте игры в конце. `profit = equity − stake`, `fee` — 10% прибыли, `payout` — сколько ABIE вернулось, `net` — итог в ABIE с учётом ставки.
- Если матч не завершили (закрыли приложение, сел телефон), через 3 минуты 3 секунды после начала сервер сам закрывает его и возвращает ставку целиком, без комиссии. В статистику такой матч не идёт.
- Сейчас сервер доверяет `place` и `equity`. На следующем шаге он сам проиграет матч по `seed` и `actions` и вычислит итог. Тогда же закроется лазейка «закрыть приложение, когда проигрываешь»: сейчас такой матч возвращает ставку.
